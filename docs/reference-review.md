# 文书引用核对

文书保存、事实确认和文书审核是三个独立操作。事实确认表示医生核实了该事实；文书仍需引用当前事实，并由医生核对正文是否需要调整。

## 章节快照

每个文书章节保存 `facts_snapshot: {fact_id: revision}`。普通保存及修改其他章节不会自动推进已有引用的版本。一个事实被多个章节引用时，每个章节分别核对；文书级 `facts_snapshot` 保留这些引用中的最旧版本。旧数据没有章节快照时，服务端沿用该历史文书的全局快照，无需数据库迁移。

审核返回的 `fact_changed` 包含 `block_key` 和 `fact_id`。事实已更正但旧正文尚未核对时，该项持续阻止审核，医生编辑正文后也不会自动消除。

## 显式核对

`PATCH /api/v1/notes/{note_id}` 的章节对象可附带：

```json
{
  "key": "allergies",
  "title": "过敏史",
  "text": "医生核实后的正文",
  "fact_ids": ["fact-id"],
  "reference_review": {
    "fact_revisions": {"fact-id": 2},
    "reason": "已核对本章正文与当前过敏史"
  }
}
```

请求仍须提交 `base_revision` 和模板全部章节。`fact_revisions` 必须恰好覆盖该章节所有引用，值必须是医生核对时看到的事实版本。说明去除首尾空白后至少三个字符。服务端记录当前医生、时间和版本，不接受客户端伪造核对身份。

事实在对话框打开后再次变化时返回 HTTP 409 `fact_revision_conflict`，文书不产生新版本。引用集合不一致返回 `invalid_reference_review`。重新获取事实并完成核对后再提交，不能通过无条件更新版本处理冲突。

## 新事实的处置

会话中新增的患者事实、主体未确定的事实，以及适用的家族史，如果属于当前文书模板且尚未被引用，会产生 `unincorporated_fact` 阻断项。事实即使已确认也需要处置。医生可以将其纳入相应章节，或在事实核查中说明原因并设为 `excluded`。问句、已排除事实、不属于当前模板的章节以及错误主体的非家族史不强制纳入。

排除后如旧正文仍引用该事实，应删除对应引用并重新核实正文；排除不会自动擦除医生文本。系统不能证明医生所写内容与引用语义一致，也不能保证发现全部临床矛盾。

工作台中可打开各章的“章节来源”，查看当前文书会话内的事实、选择引用并明确插入原文，也可移除已排除的旧引用并手工修订正文。章节保留引用时须填写核对说明并保存文书；全部引用移除后不再提交空引用核对，正文和引用变更由文书版本记录保存，事实排除理由仍单独保留。新增引用发生版本冲突后，重试和继续编辑正文都会保留已见版本约束；重新核对后才能提交新版本。明确重新载入服务端文书时，会同时放弃本地正文和未提交的引用核对。

## 回归锚点

`backend/tests/test_reference_review.py` 覆盖普通保存不能消除旧引用、逐章节核对、并发事实版本冲突、迟到病史的纳入或排除，以及模板与主体范围。`frontend/tests/note-usability.mjs` 覆盖上述医生操作、失败重试、重载和移动布局。测试使用虚构事实，不代表真实医院质量验收。
