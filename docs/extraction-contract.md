# Grounded Fact Extraction

`POST /api/v1/sessions/{session_id}/extract-facts` requires a doctor/reviewer bearer identity and returns HTTP 202 with a persistent `fact_extraction` job. No request body is required. Poll the existing job endpoint or session event stream, then refresh the facts list on `facts.extracted`. Successful results expose `fact_ids`, `skipped_source_ids`, model/prompt versions, and `requires_physician_review=true`.

Stable/final ASR results automatically enqueue extraction when `HIS_MODEL_PROVIDER=openai_compatible`, `HIS_LLM_BASE_URL`, and `HIS_LLM_MODEL` are configured. The existing approved-host policy and API credential apply. The endpoint must support chat completions with strict JSON-schema responses. Demo/unavailable mode performs no semantic extraction: automatic attempts emit `fact_extraction.unavailable`, and explicit jobs fail with `extraction_unavailable` while retaining original transcripts.

Each job fixes transcript revisions and body digests, related fact revisions, encounter source version, and configured model/endpoint. Publication rechecks these snapshots under the session lock and the current worker generation/lease. Stale results publish no facts. Raw ASR placeholders become superseded only when accepted grounded quotes cover their entire source text; partial extraction retains the raw placeholder and returns `partially_extracted_source_ids`. Transcript and fact revision evidence remains stored.

The model classifies sections, speaker, clinical subject, polarity, certainty, elicitation and medication status independently. Every candidate quotes one exact contiguous transcript span using zero-based Unicode code-point offsets with an exclusive end. Displayed fact text is the validated quote, never generated prose. Medication subfields and clinical time must be quoted substrings; normalized values remain unset. Questions and unasked/refused/unverifiable information cannot become definite findings. Model confirmation fields are forbidden; candidates are always unconfirmed and never automatically acquire physician-source authority.

Prompt version 1.1 additionally requires complete sentence or utterance context, including terminal punctuation. The server rejects a span that starts or ends inside a sentence with `incomplete_evidence_context`, so a symptom substring cannot silently omit a preceding denial or a following qualification. Commas, semicolons and decimal points are not sentence boundaries. Invalid candidate sets publish no facts and retain the original transcript. Jobs queued under a different prompt version fail with `prompt_version_changed`; enqueue a new extraction against the current contract.

This boundary check is conservative and does not prove semantic correctness. ASR sentence punctuation can itself be wrong, and context can span multiple sentences. Regression fixtures cover clipped negation, current/historical/stopped medication, a family member reporting patient history, and relative time in an older session. They do not establish acoustic recognition accuracy or clinical model accuracy.

Candidate extraction does not edit note blocks. Existing physician corrections, exclusions and confirmations suppress overlapping candidates, including after source-revision changes. Doctor verification and the normal document review/export gates remain required. Tests use an HTTP model fixture; they validate contracts and failure handling, not clinical model accuracy or approved hospital deployment.

The initial extraction request is bounded to 100 stable transcripts and 60,000 source characters. Oversized explicit requests return HTTP 413; oversized automatic requests retain the ASR transcript and emit an unavailable event for manual handling. Clinical quality, model-specific schema support, latency and real hospital workflows require separate provider and clinical acceptance tests.
